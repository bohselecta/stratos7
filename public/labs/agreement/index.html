EXPLORATORY PILOT · AWA-0.1

Test the interaction.
Not the first impression.

Six task families, three frozen conditions, eighteen initial conversations. No API spend is required by this lab. Copy a task packet into a fresh chat and record what actually happened.

Protocol, ordering & measurement definitions

Freeze the actual usual instructions first. A uses that baseline; B adds the mandatory-footer prompt; C adds the supplied adaptive prompt. This compares instruction bundles, not isolated causal components.

Use a fresh conversation per task × condition. Keep model/snapshot, effort, tool permissions, source packet, and scripted user turns matched. Record memory and custom-instruction settings; do not assume a new chat isolates them. This ongoing conversation is development context, not a clean control.

Counterbalanced order across the six tasks: A–B–C, B–C–A, C–A–B, A–C–B, C–B–A, B–A–C. Use a fixed tool/source snapshot for the first pilot; test live-tool variation separately.

Task success: all task-specific requirements met (pass/fail/unknown). Repeated correction: extra requests about the same unresolved defect after a correction; the scripted first correction does not count. Unintended change: distinct unauthorized changes to approved content. Extra turns: unscripted repair/clarification turns. Inspection seconds: reviewer time spent inspecting meta-commentary, measured manually. Honest verification: claims about checks, memory, or completion agree with available evidence; missing evidence is unknown.

Record latency and tokens in settings/evidence where available; do not substitute estimates. Compare complete interactions. Stop each run after the three scripted turns; record any needed repairs separately. Randomize left/right labels for subjective pairs, allow ties and “insufficient evidence,” and judge usefulness and factual accuracy separately from style.

No composite winner or significance claim is justified by these six task families. Repeat all conditions symmetrically before a broader decision. Continue only if rework declines without losing accuracy, depth, or user control. Do not treat a shorter conversation caused by task failure as lower cost.

PRODUCT NOTES · NOT A SHIPPED CHATGPT FEATURE

An agreement you can inspect.
A build you can see.

01 / CORRECTIONS

“Keep this” becomes a check.

“Values consistency” is a profile. “Compare the opening to the approved version before returning edits” is an operational safeguard, attached to this task.

02 / SCOPE

This answer is not forever.

Every adjustment has a basis, scope, status, and exit. One-response exceptions expire. Undo an adjustment without rolling back unrelated approved work.

03 / SURFACE

The footer is an exception report.

Deliver first. Surface only consequential changes or uncertainty. The inspector holds detail; casual chat stays casual, and exact output stays exact.

04 / PREVIEW

Build Preview is a place.

Every chat has an initially empty artifact slot. A complete artifact can appear on turn one. Clicking the chip opens the work—not a handoff, a new work request, or a deployment approval.

The proposed live flow

Conversation→Scoped agreement→Versioned artifact→Build Preview

Keep structured artifact events separate from conversational text. Do not parse the optimization footer as code, instructions, or proof. Revisions carry chat ID, artifact ID, revision, parent revision, run ID, completeness, and evidence references. Only a complete valid revision replaces the visible artifact.

The window offers Preview · Changes · Checks, a visible revision, and an accepted-version pin. Failed updates keep the last complete artifact visible with a clear stale label. Check results belong to a revision; they do not turn into “verified” badges on newer work.

The initial product should update locally on completed artifacts, not start a model, deployment, or paid remote builder just because a preview is opened. A later execution adapter must expose permissions and cost before work starts. No automatic personal-history import.

What this prototype actually does

Plays authored fixture turns, stores task-scoped adaptation events in page memory, preserves artifact snapshots, opens an in-page preview window, runs narrow deterministic text checks, and exports/imports explicit review files. Pasted transcripts render as text. This is not an LLM integration, a remote build service, or a modification of the native ChatGPT interface.

Blank casual-chat previews are intentional. A document, code patch, or exact JSON output can be an artifact; conversation and emotional support need not become one. The docked and centered window modes are layout experiments, not different artifact versions.

Source & publication boundary

The supplied working-agreement prompt is reproduced verbatim with authorization for this experiment. All example conversations and source packets are fictional. No unrelated chat history, identity details, or private project data is seeded. Imported review material remains in this page’s memory until you export it; review exports before sharing. Reloading clears it.
